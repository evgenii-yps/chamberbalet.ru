# chamberbalet.ru

Одностраничная презентация Камерного театра балета для менеджеров концертных
площадок. Не продажа билетов: задача — показать спектакль и снять возражение
«у нас нет сцены».

Полное задание — [`SPEC.md`](SPEC.md). Механика движения перенесена из
согласованного прототипа, он лежит в [`prototype/`](prototype/) и открывается
двойным щелчком, без сервера. Здесь — только как собрать и что залить.

---

## Коротко

```sh
npm ci          # один раз
npm run build   # результат в dist/
```

Заливаем на хостинг **содержимое** `dist/`, включая `.htaccess`.
Рантайм-зависимостей нет: на выходе статика, ноль внешних запросов.

---

## Что нужно на машине

* **Node.js 20 или новее.** Проверить: `node -v`.
* **ffmpeg** — только если собираете видеофон. Без него сборка проходит,
  просто без видео. Проверить: `ffmpeg -version`.

Больше ничего. `sharp` ставится вместе с зависимостями.

## Куда класть исходники

```
media/originals/incoming/ всё, что пришло со съёмки, как есть
media/originals/photo/    14 отобранных кадров (в сборку идут 8, см. SPEC §15)
media/originals/video/    hero.<ext>, необязательно
media/originals/fonts/    .ttf/.otf, необязательно
```

Требования к каждому — [`media/README.md`](media/README.md).

**Оригиналы лежат в git.** Это отклонение от первой редакции спецификации,
принятое осознанно: без них следующий, кто откроет репозиторий, начинает с
нуля. Четырнадцать кадров весят около 5 МБ — дешевле, чем терять раскладку.

### Как разложить съёмку по слотам

Имена файлов со съёмки **ничего не значат**: числовые префиксы не совпадают с
порядком показа. Раскладку делает сопоставление по содержимому.

```bash
# 1. сложить всё присланное в media/originals/incoming/
# 2. посмотреть таблицу — без копирования
node scripts/match-originals.mjs
# 3. если сомнительных слотов нет — разложить
node scripts/match-originals.mjs media/originals/incoming --apply
```

Скрипт считает перцептивный хэш каждого кандидата и каждого эталона
`prototype/assets/photo/NN.jpg`, сводит по минимальному расстоянию и
**отказывается копировать** слот, если совпадение неуверенное. Правильное
совпадение даёт 5–16 бит из 256, ближайшее ложное — от 45.

**Оригиналов может не быть.** Сборка это переживает: печатает, чего не хватило,
и продолжает. Так и задумано — конвейеры написаны раньше, чем сняты кадры.

## Команды

| команда | что делает |
|---|---|
| `npm run build` | полная сборка в `dist/` — то, что заливаем |
| `npm run build:debug` | то же, но незаполненные значения видны пометкой |
| `ROBOTS=deny npm run build` | то же, но `robots.txt` запрещает индексацию целиком — пока сайт не должен попадать в поиск |
| `npm run images` | только фотографии, с таблицей весов и проверкой бюджета |
| `npm run video` | только видео |
| `npm run fonts` | только шрифты |
| `npm run check` | инварианты пролёта, затемнения и контраста |
| `npm run serve` | локальный сервер над `dist/` на http://localhost:4173 |
| `npm run qa` | 53 проверки в настоящем браузере (нужен `playwright`) |
| `npm run qa:lazy` | ленивая загрузка под троттлингом 4G (нужен `playwright`) |
| `npm run qa:demo` | демонстрации перехода: секундомер на живой странице |
| `npm run lighthouse` | Lighthouse на мобильном профиле (нужен `lighthouse`) |
| `npm run lcp` | LCP медианой прогонов, две сборки вперемешку |
| `node scripts/check-contrast-photos.mjs` | контраст подписи на боевых кадрах |

`qa` и `lighthouse` ставятся отдельно: `npm i -D playwright lighthouse
chrome-launcher`. Если Chromium в системе стоит отдельно от playwright,
укажите его путь:

```bash
PLAYWRIGHT_CHROMIUM=/путь/к/chrome npm run qa
```

`npm run images`, `npm run video` и `npm run fonts` кладут результат в
`.build/assets/` и печатают отчёт — в `dist/` он попадает при `npm run build`.

Первая полная сборка с фотографиями идёт **от пяти до пятнадцати минут**,
смотря по машине: AVIF в четырёх ширинах на восемь кадров — дорогая
операция. Сборка печатает ход работы по кадрам, так что видно, что она жива.

Повторные сборки — **секунды**: закодированное лежит в `.build/assets/` и
оттуда копируется в `dist/`, а кэш в `.build/images.cache.json` помнит время
правки каждого оригинала. Чтобы пересобрать всё начисто, удалите `.build/`.

## Продакшн и отладка

Разница одна — что делать с незаполненным значением.

* `npm run build` — **блок исчезает целиком.** Лучше отсутствующий блок, чем
  `__ЗАПОЛНИТЬ__` на живом сайте.
* `npm run build:debug` — на месте значения рисуется рамка с пометкой, чтобы
  видеть, что ещё не заполнено.

Переключается переменной окружения `BUILD_MODE=debug`.

## Правка текстов

**Все строки живут в одном файле — `src/content.js`.** Разметку трогать не
нужно: `scripts/render.mjs` собирает HTML из этого объекта.

Незаполненное значение помечается константой `PLACEHOLDER`. Заполнили —
блок появился сам.

```js
export const contact = {
  name:     'Имя Фамилия',        // было PLACEHOLDER
  phone:    '+7 900 000-00-00',
  email:    'hello@chamberbalet.ru',
  telegram: '@chamberbalet',
};
```

Что нельзя выносить на сайт — в `SPEC.md`, раздел «Границы»: ставок, процентов
и сумм на странице нет; цифры не выдумываются.

## Проверки

```sh
npm run check
```

Считает числом то, что в приёмке записано словами:

* пресет масштаба даёт 1,04 при рождении и 1,149 на главе, монотонен;
* фотография никогда не меньше экрана, дрейф не открывает чёрных краёв;
* на каждой остановке ровно один слой с непрозрачностью 1 и ровно одна подпись;
* в середине перехода чёрного провала нет — плотность 100,00 % на всём пути;
* средняя плотность затемнения над фотографией не выше 40 % — иначе свечи
  перестают светиться;
* контраст кремового текста не ниже 4,5 : 1 на всех кадрах, включая самые
  светлые.

`npm run images` дополнительно печатает таблицу весов и **роняет сборку**, если
первый экран тяжелее 1,2 МБ или вся страница тяжелее 6 МБ.

### Проверки в браузере

Playwright и Lighthouse намеренно не входят в зависимости сборки: театру они
не нужны, а `npm ci` должен оставаться лёгким. Ставятся отдельно:

```sh
npm i -D playwright lighthouse chrome-launcher
npx playwright install chromium
npm run build && npm run qa && npm run lighthouse
```

`npm run qa` открывает собранную страницу в Chromium и проверяет сорок три
вещи из приёмки: чистоту консоли, отсутствие внешних запросов, «один жест —
одна глава», отпускание прокрутки после пролёта, поведение без JS и при
`prefers-reduced-motion`, покрытие экрана кадром на десктопе и на телефоне,
а по пикселям — что подпись действительно нарисована поверх кадра.
Скриншоты кладутся в `.build/shots/`.

Если Chromium установлен отдельно от playwright, путь к нему задаётся
переменной `PLAYWRIGHT_CHROMIUM`.

## Деплой на рег.ру

### Что собрать

```bash
npm ci                 # один раз
npm run build          # результат — dist/
npm run check          # инварианты пролёта и затемнения, должно быть «сходится»
```

Собранное лежит в `dist/`. Заливать нужно **содержимое** этой папки, а не саму
папку. Внутри:

```
dist/
├── index.html         ← отдаётся с no-cache, обновляется на месте
├── .htaccess          ← кэш, сжатие, HTTPS, www → без www
├── assets/            ← css, js, шрифты, фотографии; в именах хэш содержимого
├── favicon.svg, apple-touch-icon.png, site.webmanifest
└── robots.txt, sitemap.xml
```

### Что залить

1. `npm run build`
2. Открыть файловый менеджер панели рег.ру или подключиться по FTP/SFTP.
3. Перейти в корень сайта — обычно `/var/www/<логин>/data/www/chamberbalet.ru/`.
4. **Удалить старое содержимое** каталога.
5. Залить **всё содержимое** `dist/` — не саму папку `dist`, а то, что внутри.
6. Убедиться, что `.htaccess` доехал. Многие FTP-клиенты прячут файлы с точки:
   включите показ скрытых файлов.

Проверить после заливки:

* `https://chamberbalet.ru` открывается, `http://` и `www.` редиректят на неё;
* в консоли браузера пусто;
* `https://chamberbalet.ru/robots.txt` и `/sitemap.xml` отдаются.

### Почему можно спокойно перезаливать

Все файлы в `assets/` содержат хэш содержимого в имени и отданы с вечным кэшем.
Изменился файл — изменилось имя, браузер возьмёт новый. `index.html` отдаётся
с `no-cache`, поэтому новые имена подхватываются сразу.

Отсюда правило: **не заливайте `assets/` поверх, не обновив `index.html`.**
Проще всего заливать `dist/` целиком.

### Если что-то не так

* **Страница без стилей.** Не доехала папка `assets/`.
* **Нет редиректа на HTTPS.** Не доехал `.htaccess` либо на хостинге выключен
  `mod_rewrite` — включается в панели.
* **Внутренняя ошибка 500.** Хостинг не знает какой-то директивы из `.htaccess`.
  Все рискованные обёрнуты в `<IfModule>`; если это всё же случилось, уберите
  блок `mod_headers` и напишите в поддержку.

## Структура

```
src/content.js      ← ВСЕ тексты. Единственный файл для правок содержания
src/index.html      шаблон: ни одной видимой строки, только слоты
src/css/            tokens · base · flight · sections
src/js/             flight (кадровый цикл) · nav (ввод) · hero-video · reveal · main
scripts/            конвейеры медиа и шрифтов, рендер разметки, проверки
prototype/          согласованный прототип: справка по движению
media/originals/    оригиналы, в git не коммитятся
dist/               результат сборки, его и заливаем
.htaccess           кэш, сжатие, HTTPS, www → без www
```

Фреймворков нет, рантайм-библиотек нет. Сборка нужна только для медиа, шрифтов
и подстановки текстов; HTML, CSS и JS едут как есть, без минификации —
читаемость важнее сэкономленного килобайта.
