# Пакет заданий Codex — сайт chamberbalet.ru

Дата подготовки: 21.11.2026. Статус: **пакет ТЗ подготовлен, сайт не создан и не опубликован**.

## Что делать пользователю

1. В новую сессию Codex передать **этот ZIP** и файл `START_HERE_CODEX.md` как главное поручение.
2. Передать ссылку на **действующий макет**: https://chamberbalet-prototype-v01.cuppedhornbill2.chatgpt.site/
3. Для визуальной подсказки при необходимости отправить HTML v0.19 и исходники из библиотеки (ссылки в `REFERENCE/REFERENCE_MANIFEST.md`). **Это неполная автономная копия, а не экспорт действующего Sites-макета.**
4. Codex приступает только к **STAGE 00**: проверяет доступность исходного Sites-проекта, сравнивает с GitHub и выдаёт точный список недостающего. Если нет полного экспорта, останавливается и объясняет, как его получить.
5. После отчёта STAGE 00 отдельно дать разрешение на следующий пакет, когда его условия выполнены.

## Как устроены файлы

- `START_HERE_CODEX.md` — входное поручение; авторизован этап 00.
- `AGENTS.md` — правила для инженера, если архив распакован в рабочую папку Codex.
- `PROJECT_CONTRACT.md` — что считаем подтверждённым и что запрещено подменять.
- `TASKS/STAGE_00_*.md` ... `TASKS/STAGE_06_*.md` — отдельные, достаточно самостоятельные ТЗ. В каждом повторена полная дорожная карта и условие перехода.
- `REFERENCE/REFERENCE_MANIFEST.md` — где лежат оригинальный URL и доступные вспомогательные файлы.
- `REFERENCE/OPEN_REFERENCE.html` — удобный файл для открытия нужных ссылок. **Не исходник сайта.**
- `TEMPLATES/` — схемы отчёта, матрицы соответствия и релизного манифеста.
- `OWNER/REG_RU_RELEASE_GUIDE_RU.md` — объяснение ручной публикации и отката владельцу.

**Важно:** в этот архив не включён полный экспорт оригинального Sites-макета, потому что источник не выдал свои файлы из этой среды. Он НЕ заменён произвольной реконструкцией. Codex должен получить оригинал через разрешённый ему доступ/экспорт перед реализацией.
