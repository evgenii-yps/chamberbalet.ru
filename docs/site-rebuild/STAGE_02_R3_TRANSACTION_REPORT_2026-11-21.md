## Implemented

- Private version store writes events, People, aligned baseline and audit ledger into one hash-addressed immutable JSON snapshot, verifies it, then atomically renames one active-pointer file. A lock excludes concurrent writers; stale plan/active pointer, parent mismatch, repeated canonical input, duplicate IDs, invalid dates, invalid status fields, corrupt snapshots and symlink directories are rejected. Rollback produces a new audited snapshot pointing at data from a previously active snapshot; it does not erase history. A dead-owner lock can be recovered only after checking the recorded PID and validating active state.
- `build-private.mjs` consumes an active verified snapshot when a store exists; otherwise it preserves the legacy private-data path. It validates original 57-file v16 source and checks portrait paths. A legacy-file guard detects changes to original editable files before a CLI promotion or build. An explicitly reviewed reactivation clears a previous cancellation; review evidence is required for changed/ambiguous matches, and prior cancellation and ticket evidence remain in record history. Source URL changes invalidate ticket approvals.
- Revision ID is SHA-256 of the incoming array's canonical `JSON.stringify` bytes and plans bind the active snapshot, parent and editor state. It is a content identity, not authenticated proof of a real upstream Git ancestry: a caller can misstate the source parent. Repeated identical content is rejected even if legitimately republished later. This prevents some valid sequences and does not independently prove source history.
