# Оригиналы

Содержимое этой папки **коммитим в git** — иначе следующий, кто откроет
репозиторий, начинает с нуля. Осознанное отклонение от первой редакции
`SPEC.md` §3, там же оно и записано.

## Куда что класть

### `incoming/` — сюда кладутся оригиналы

Всё, что пришло со съёмки, **с любыми именами**: `SDS_6029.jpg`, `DSC_0042.NEF`,
что угодно. Разбирать и переименовывать руками не нужно — имена файлов со
съёмки не значат ничего, числовые префиксы не совпадают с порядком показа.

### `photo/` — заполняется автоматически

**Руками сюда ничего не класть.** Папку заполняет
[`scripts/match-originals.mjs`](../scripts/match-originals.mjs): он сравнивает
каждый кадр из `incoming/` с эталонами прототипа по содержимому
(перцептивный хэш) и раскладывает четырнадцать отобранных под именами слотов.

```bash
node scripts/match-originals.mjs                              # таблица, без копирования
node scripts/match-originals.mjs media/originals/incoming --apply   # разложить
```

Сначала всегда прогон без `--apply` — посмотреть таблицу глазами. Скрипт
отказывается копировать слот, если совпадение неуверенное.

## `photo/` — имена слотов

Их проставляет `match-originals.mjs`. Имена берутся из `src/content.js`
(поле `photo`), расширение любое из `.jpg .jpeg .png .tif .tiff .webp .avif`:

```
01-hall-piano.jpg        08-sugarplum-costume.jpg  ← вертикальный
02-hall-wide.jpg         09-costume-close.jpg
03-seats-arc.jpg         10-mansion-tree.jpg
04-candle-arc-top.jpg    11-snow-scene.jpg
05-backdrop-solo.jpg     12-stage-top.jpg
06-duet-candles.jpg      13-soloist-ready.jpg
07-nutcracker-duet.jpg   14-finale.jpg
```

Что на каждом кадре — в `alt` в `src/content.js`. Порядок и содержание взяты
из согласованного прототипа (`prototype/index.html`), там же можно посмотреть
черновые версии кадров.

Восемь из четырнадцати несут главу, остальные проходные: камера пролетает их
внутри перехода. Проходной кадр виден меньше секунды, но виден во весь экран —
требования к нему те же.

Требования:

* минимум **2560 px** по длинной стороне, целевое **3200 px**;
* без предварительного сжатия, без ресайза, без вотермарков;
* горизонтальные, кроме помеченных в `content.js` как `tall: true`;
* цветовой профиль любой — сборка принудительно приводит к sRGB.

Оригинал меньше 2000 px не роняет сборку, но печатает предупреждение с именем
файла и фактическим размером.

Кадр показывается вплоть до масштаба 2,6 — то, что «выглядит достаточно
крупным» на глаз, почти наверняка недостаточно. Отсюда 3200 px.

## `gallery/` — кадры секции «Ещё кадры»

Двенадцать фотографий, которых НЕТ в пролёте: секция отвечает на «покажите
больше, чем восемь кадров», а не пересказывает их. Имена слотов берутся из
`gallery.items[].photo` в `src/content.js`.

Требования те же, что к `photo/`: от 2560 px по длинной стороне, без
предварительного сжатия и вотермарков. Вертикальные допустимы — миниатюра
режется в 3 : 2 по области с наибольшей детализацией, полноразмер в лайтбоксе
показывает кадр целиком.

Производные считает тот же `npm run images`:

```
gallery/<слот>.jpg
    → dist/assets/gallery/<слот>-640.<хэш>.webp    миниатюра, q58, ≤ 55 КиБ
      dist/assets/gallery/<слот>-1600.<хэш>.webp   полноразмер, q72, ≤ 260 КиБ
```

Замена кадра: положить файл под тем же именем и прогнать `npm run images`.
Добавление кадра: строка в `gallery.items` плюс файл. Отсутствующий оригинал
сборку не роняет — кадр просто выпадает из галереи, и это печатается.

## `video/`

Здесь живут ДВА разных ролика, и путать их не надо.

### `hero.<ext>` — фон первого экрана

* без звука;
* 6–12 секунд;
* первый и последний кадр совпадают — иначе петля будет дёргаться;
* горизонтальный, от 1920 × 1080;
* сюжет спокойный: поверх лежит заголовок.

Ролика может не быть. Тогда сборка печатает «фон первого экрана не найден»,
а первый экран живёт на фотографии `01-hall-piano`.

### `stage.<ext>` — ролик секции «Как это выглядит в зале»

Имя берётся из `videoSection.basename` в `src/content.js`.

* со звуком: его включает зритель, автовоспроизведения нет;
* 40–60 секунд по ТЗ правки 06;
* H.264 High, до 1,6 Мбит/с, до 12 МиБ;
* горизонтальный 16 : 9 — либо вертикальный, тогда `vertical: true`.

Перекодирования по умолчанию НЕТ: если исходник уже укладывается в потолок
битрейта, делается только ремукс с `+faststart`, чтобы браузер начинал играть,
не дождавшись конца файла. Выше потолка — сборка перекодирует сама.

Постер снимается с секунды `videoSection.posterAt`, идёт в WebP q60 и ставится
на элемент ИЗ JS, когда секция входит в область просмотра: в разметке атрибута
`poster` нет намеренно, иначе картинка уехала бы в первую загрузку.

Сборка печатает предупреждение, если кадр вертикальный или длительность вне
полосы 40–60 с — молча такие расхождения не проходят.

**Нужен ffmpeg.** Он объявлен в `devDependencies` (`ffmpeg-static`), потому что
ролик — это содержание страницы, а не украшение: сборка без него тихо отдала бы
страницу без секции видео.

## `fonts/`

Необязательно. Если сюда положить оригиналы `.ttf`/`.otf`, они пойдут в
настоящий субсеттинг через `subset-font`:

```
CormorantGaramond-400.ttf   CormorantGaramond-600.ttf
Manrope-400.ttf             Manrope-500.ttf
```

Если папка пуста, шрифты берутся из пакетов `@fontsource/*`, которые уже стоят
в `devDependencies`. Внешних запросов к шрифтовым сервисам нет ни в том, ни в
другом случае.

**Курсив Cormorant Garamond не подключать ни при каких обстоятельствах:** он
переопределяет кириллицу и портит русский текст.
